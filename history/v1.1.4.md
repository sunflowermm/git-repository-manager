## 🌻 向日葵Git仓库管理 v1.1.4

### 🔧 优化

- **Gitee / GitCode 提交文案显示行数**：之前「提交并同步」先提交主仓再同步，主仓已无变更，从仓无法生成带行数的提交信息。现改为只调用一次 `sync-repos`，由它统一完成主仓提交、推送和同步，主仓与从仓（Gitee、GitCode）均使用同一份包含 `[✏️ 3 修改, ➕ 2 新增, 🗑️ 1 删除] +123 -45 行` 的完整提交信息。
- **修改 / 删除使用不同 emoji**：提交信息与文件列表统一使用：✏️ 修改、➕ 新增、🗑️ 删除、🔄 重命名，前后端一致。
- **多从仓与统一流程**：`sync-repos` 支持多从仓 `subordinates: [{ path, config }, ...]`；主仓只提交一次，所有从仓使用同一份 `fullMessage`（含行数统计）；删除文件检测已修正，可正确识别 `D`、` D` 等状态。

### 📋 当前流程

1. 用户点击「提交并同步」→ 构建从仓列表 `subList`
2. 调用 `sync-repos(mainPath, subList, message, config)`
3. **主仓**：`add` → 生成 summary + lineChanges → `commit(fullMessage)` → `push`
4. **各从仓**：若与主仓同 remote 则 `pull`，否则复制内容 → `commit(fullMessage)` → `push`

Gitee、GitCode 等从仓的提交记录均会显示完整的变更统计和行数信息。

### 🧱 底层完善

- **提交信息构建**：主仓与从仓共用同一套 `generateCommitSummary` + 行数统计，抽离 `getLineChangesFromStatus` 与 `buildFullCommitMessage`，避免重复逻辑。
- **删除状态判定**：统一使用 `isDeleted(s)`（`trim` 后为 `'D'`），兼容 `D`、` D` 等 git status 输出。
